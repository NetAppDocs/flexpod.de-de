NetApp unterstützt mehrere optionale Komponenten, um FlexPod Datacenter-Architekturen noch weiter zu verbessern. Optionale Komponenten werden in den folgenden Abschnitten beschrieben.


NOTE: SAN Boot ist optional, wird aber dringend empfohlen, da es die Verschiebung von Serverprofilen bei Hardware-Upgrades oder Austausch ermöglicht.



[[iscsi-boot-option]]
== ISCSI-Boot-Option

Die Mindestanforderungen für die iSCSI-Bootoption umfassen:

* Eine iSCSI-Lizenz/-Funktion ist auf dem NetApp Storage Controller aktiviert
* Einen 2-Port 10 GB/s Ethernet Adapter auf jedem Node im NetApp Storage Controller HA-Paar
* Ein Adapter im Cisco UCS Server, der iSCSI Boot unterstützen kann

[[fc-boot-with-cisco-mds]]
== FC Boot mit Cisco MDS

Um durch die Nutzung eines dedizierten SAN-Netzwerks eine höhere Skalierbarkeit zu bieten, unterstützt FlexPod FC über Cisco MDS Switches. Die FC SAN Boot-Option über Cisco MDS hat die folgenden Lizenz- und Hardwareanforderungen:

* Mindestens zwei FC-Ports pro NetApp Storage Controller, ein Port pro SAN-Fabric
* Eine FC-Lizenz auf jedem NetApp Speichercontroller.
* Ein Adapter im Cisco UCS Server, der FC-Boot unterstützt.

[[end-to-end-fc-nvme]]
== End-to-End FC-NVMe

Eine durchgängige FC-NVMe-Lösung erweitert die bestehende SAN-Infrastruktur eines Kunden nahtlos für Echtzeitanwendungen und bietet gleichzeitig verbesserte IOPS und höheren Durchsatz bei reduzierter Latenz. Ein vorhandener 32G FC SAN-Transport kann genutzt werden, um NVMe- und SCSI-Workloads gleichzeitig zu übertragen.

Weitere Informationen zu dieser Konfiguration sind unter link:https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_m7_imm_vmware_design.html#PhysicalTopology["FlexPod Datacenter mit Cisco UCS M7 IMM, VMware vSphere 8.0 und NetApp ONTAP 9.12 Designleitfaden"^] zu finden.

== Cisco UCS X-Series Direct und direkt angeschlossene AFF/ ASA/ FAS für FC- und IP-basierte SAN

NetApp Storage-Controller können direkt an die Cisco UCS Fabric Interconnects ohne vorgelagerten SAN-Switch angeschlossen werden. FlexPod unterstützt sowohl FC- als auch iSCSI-Boot mit UCS X-Series Direct.

Die Lizenz- und Hardwareanforderungen lauten wie folgt:

* Auf dem NetApp Storage Controller ist eine Protokolllizenz erforderlich.
* Auf dem Server wird ein Cisco UCS-Adapter (Initiator) benötigt. Eine Liste der unterstützten Cisco UCS-Adapter befindet sich in der NetApp https://imt.netapp.com["IMT"^].
* Auf dem NetApp Storage Controller ist ein Target-Adapter erforderlich.

[[metrocluster]]
== MetroCluster

FlexPod MetroCluster IP mit VXLAN Multi-Site Fabric-Lösung besteht aus zwei FlexPods, die sich an zwei durch eine gewisse Distanz getrennten Standorten befinden, aber miteinander verbunden und gepaart sind, um eine hochverfügbare, hochflexible und hochzuverlässige Datenzentrums-Lösung bereitzustellen, die Geschäftskontinuität auch bei einem Standortausfall ermöglicht. Die maximal unterstützte Entfernung zwischen den Standorten beträgt etwa 435 Meilen (700 km).

In der FlexPod MetroCluster IP-Lösung ermöglicht die Cisco VXLAN Multi-Site-Lösung die Verbindung und zentrale Verwaltung von VXLAN-Fabrics, die in separaten, geografisch verteilten Rechenzentren bereitgestellt sind. NetApp MetroCluster IP bietet eine synchrone Replizierungslösung zwischen zwei NetApp Storage-Clustern und gewährleistet so hohe Speicherverfügbarkeit und Disaster Recovery auf einem Campus oder im Großraumgebiet. Die Lösung ermöglicht die Konzeption einer VMware vSphere-basierten Private Cloud auf einer verteilten, integrierten Infrastruktur und die Bereitstellung einer einheitlichen Lösung, die es mehreren Standorten ermöglicht, sich weitgehend wie ein einzelner Standort zu verhalten, während Datendienste vor verschiedenen Single-Point-of-Failure-Szenarien, einschließlich eines vollständigen Standortausfalls, geschützt werden.

[[snapmirror-active-sync-solution-for-flexpod-metrocluster-ip-solution]]
=== SnapMirror Aktiv/Aktiv-Sync-Lösung für FlexPod MetroCluster IP-Lösung

Mithilfe der NetApp Snapshot Technologie in NetApp ONTAP Software können unternehmenskritische SAN-Datendienste schnell mit Daten aus Snapshot-basierten Backups wiederhergestellt werden.

* Die beiden an zwei verschiedenen Standorten eingesetzten ONTAP Cluster sind per Peering verbunden und mit SnapMirror active sync für synchrone Datenreplizierung und Notfallwiederherstellung konfiguriert.
* Der ONTAP Mediator wird in einer dritten Ausfalldomäne eingesetzt, wie in der Abbildung unten dargestellt. Zusammen mit den Clustern vervollständigt der ONTAP Mediator das Quorum für die SnapMirror Aktiv/Aktiv-Synchronisierungslösung.
* Der ONTAP Mediator empfängt Statusinformationen von den verbundenen ONTAP Clustern und -Knoten und koordiniert die Kommunikation zwischen ihnen, um ihren Status zu ermitteln. Die Statusdaten helfen den Clustern, verschiedene Fehlertypen zu unterscheiden und zu entscheiden, ob ein automatisches Failover durchgeführt werden soll.

=== Symmetrische Aktiv/Aktiv-Mehrwegeunterstützung für FlexPod MetroCluster IP Lösung

Damit Hosts/Clients die replizierten LUNs nutzen können, werden im Remote-Cluster igroups erstellt, die replizierten LUNs den entsprechenden igroups zugewiesen und die Hosts/Clients so eingerichtet, dass sie das iSCSI-Ziel und die vom Remote-Cluster verfügbaren LUNs als zusätzliche Pfade erkennen können.

Wie in der Abbildung unten dargestellt, können Unternehmensanwendungen auf einem Speicherclient mithilfe von iSCSI-basierten LUNs bereitgestellt werden, die von zwei ONTAP ASA Clustern gehostet werden, die für synchrone Datenreplizierung zwischen Standorten konfiguriert sind.
